第一章　概述：先理解网络为什么这样设计

1.1 三种交换方式：比较的是资源怎样分配

对应：1A 第 3–16 页；第一次作业讲解第 2 页。

先问自己：如果说完一句话要停一会儿，还值得一直独占整条线路吗？计算机数据具有突发性，这正是分组交换适合数据通信的重要原因。

方式 传输前与传输中 转发单位 主要得失
电路交换 先建立连接，期间保留通信资源，最后释放 连续比特流 资源有保障；空闲时仍占资源，需建立时间
报文交换 整个报文收齐后再转发 完整报文 不必专占线路；大报文的缓存和等待开销大
分组交换 报文分段，各分组携带控制信息，逐跳转发 分组 可流水线、按需共享；有首部、排队和处理开销

重点：存储转发意味着一个结点通常先收完整个转发单位，才向下一跳发送；分组之间可以在不同链路上并行推进。

不要背成绝对结论。分组交换有较好的生存性，不等于每个分组都保证送达；不同分组可能走不同路径，但不要求它们必须走不同路径。分组长度也不必在所有网络中固定相等。

填空 F01　电路交换经过________、________、________三个阶段。分组交换中的中间结点通常采用________方式转发。

参考答案：建立连接；传送数据；释放连接；存储转发。

简答 S01　为什么把大报文切成分组可能缩短多跳传输时间？代价是什么？

参考答案：下游结点收齐第一个分组后即可转发，不必等整个报文到达；此时上游还可继续发送后续分组，形成流水线。代价是每个分组都要携带首部并被处理，可能排队、丢失或乱序，接收端还需相应的重组与可靠性机制。

例题 E01｜老师作业中的流水线　文件大小 40 Mb，每个分组 1 Mb，两条链路均为 20 Mb/s，中间一个存储转发路由器。忽略传播、排队、处理及首部开销。电路方案建立连接需 1 s。求两种方案的完成时间。

参考答案与过程：

  • 电路交换：1+40/20=3 s1+40/20=3\text{ s}。
  • 分组数 P=40P=40，链路数 H=2H=2，单包发送时间 t=1/20=0.05 st=1/20=0.05\text{ s}。
  • 第一个包到达需 2t2t，此后每隔 tt 到达一个包，故总时间为 (H+P−1)t=41×0.05=2.05 s(H+P-1)t=41\times0.05=2.05\text{ s}。

难点：这里数的是 2 条链路，不是 1 台路由器；不能算成 40×2×0.05=440\times2\times0.05=4 秒，那会把本可并行的传输全部串行化。

补充公式：等长分组、各跳同速率且没有其他开销时，T=(P+H−1)L/RT=(P+H-1)L/R；若有传播时延，再加各链路传播时延之和。不同速率链路不能直接套这个同速率公式。

1.2 端、网、云与 C/S、P2P

对应：1A 第 33–48 页；作业讲解第 3–4、9 页。

网络边缘包含端系统及其接入部分，运行应用、产生和消费数据；网络核心由分组交换结点及互连链路组成，主要提供连通和转发。云计算把资源集中到远端，边缘计算把部分计算与服务放到靠近用户的位置，以减少远端访问时延。

比较点 C/S P2P
角色 客户进程请求，服务器进程提供服务 一个结点可同时请求和提供服务
大规模分发 中心的上传带宽、处理能力可能成瓶颈 参与者可贡献缓存与上传带宽
管理 较集中，易于统一控制 节点发现、调度、协同更复杂
故障 中心故障可能影响大量用户 单个普通节点退出通常可由其他节点弥补；混合系统仍可能依赖中心协调

重点：视频分发中“服务器上传带宽”指服务器把视频发给用户的出站带宽；P2P 用户可以把已经缓存的片段传给其他人，不要求视频由该用户原创或首次上传。

接入技术记“原有介质＋如何接入”：DSL 利用电话双绞线与 DSLAM；Cable 利用有线电视设施并共享部分接入资源；FTTH 为光纤到户；企业常用以太网、Wi-Fi；移动接入依靠蜂窝网络。不要把 Wi-Fi 与整个 Internet 等同。

简答 S02　为什么用户越多，P2P 的扩展能力可能越强？是否意味着不用服务器，也没有带宽限制？

参考答案：新增用户带来下载需求，也可能增加缓存副本和上传能力，分担原来由中心承担的分发压力。但收益取决于用户在线、可用片段、上传能力和调度效果；混合 P2P 仍可有管理服务器，每个用户和路径也都有带宽限制。

1.3 性能指标：看到“快”要问清到底快在哪里

对应：1A 第 50–64 页；作业讲解第 5–6 页。

重点：带宽是容量指标，吞吐量是实际交付速率，时延是一次传输花的时间。三者不能互换。

发送时延 ttx=L/Rt_{\mathrm{tx}}=L/R LL 用 bit，RR 用 bit/s
传播时延 tprop=d/vt_{\mathrm{prop}}=d/v 距离、介质中的传播速度
处理、排队时延 首部处理、查表、缓存等待等 题目是否给出或允许忽略
总时延 各次处理、排队、发送、传播时延相加 多跳要逐跳计，注意流水线

例题 E02｜把三种“快慢”分开算

（1）8 Mb 数据经过 4 Mb/s 链路，距离 600 km，传播速度 2×1082\times10^8 m/s，求发送和传播时延。

参考答案：发送时延 8/4=28/4=2 s；传播时延 600000/(2×108)=0.003600000/(2\times10^8)=0.003 s，即 3 ms。若无其他开销，最后一比特到达需 2.003 s。

（2）600 MB 文件经过 100、20、50 Mb/s 的串行路径，按稳定流水传输、忽略协议开销与起始填充时间估算。

参考答案：瓶颈为 20 Mb/s；文件为 4800 Mb，时间约 4800/20=2404800/20=240 s。这是大文件稳态估算，不是把整份文件在三条链路上的发送时间逐一相加。

（3）1 Gb/s 链路，RTT 为 100 ms，请求后返回 1 MB 数据，采用课件的简化模型 T=RTT+L/RT=RTT+L/R。

参考答案：L/R=8L/R=8 ms，T=108T=108 ms；有效吞吐量为 8 Mb/0.108 s≈74.18\text{ Mb}/0.108\text{ s}\approx74.1 Mb/s，远低于 1 Gb/s。若路径对称且 RTT 全由传播构成，单程链路容积为 109×0.05=5010^9\times0.05=50 Mbit；覆盖一个 RTT 的在途数据量量级为 100 Mbit。二者差一倍，含义不同。

补充理解：小请求常受往返时延支配，大文件更可能受瓶颈带宽支配。课件利用率公式 D=D0/(1−U)D=D_0/(1-U) 是特定排队假设下的近似模型，表达的是高负载下排队时延急剧增加，不是任意网络都精确成立的定律。

1.4 分层、协议、服务与封装

对应：1B 第 3–27 页。

重点：协议是不同系统的对等实体之间的规则；服务是同一系统中下层通过接口为上层提供的能力。协议“横向”，服务和接口“纵向”。

协议的三要素：语法规定报文格式；语义规定字段含义及动作；同步规定事件的次序与时序约束。分层的价值是分解复杂性、隐藏实现、稳定接口、便于替换和标准化；代价是额外首部与跨层协作开销。

自上而下 OSI 七层 本课理解用五层 常见数据单元
应用功能 应用、表示、会话 应用层 应用数据／报文
进程之间 传输 传输层 TCP 段、UDP 数据报
网络互联 网络 网络层 IP 数据报／分组
相邻结点 数据链路 数据链路层 帧
介质信号 物理 物理层 比特

课件 TCP/IP 使用应用、传输、IP、子网层的四层表示；五层是把子网层拆成链路和物理，答题时应注明所用模型。IP 是“细腰”：上面承载多种应用和传输协议，下面适配多种链路技术。

封装：应用数据 → 加传输首部 → 加 IP 首部 → 加链路首部及尾部 → 编码为信号。接收方向相反。经过路由器时，剥去入站链路封装，查看 IP，再按出站链路重新组帧；通常不需要把应用数据一直解到应用层。

填空 F03　协议三要素是________、________、________。以太网帧中的类型字段用于区分________协议；IP 首部中的 Protocol 字段用于区分________协议。

参考答案：语法；语义；同步；上层，例如 IPv4 或 ARP；IP 载荷所用的上层协议，例如 TCP、UDP、ICMP。它不是直接区分用户进程的端口号。

简答 S03　“同层实体在直接通信”这句话怎样理解？为什么修改某一层的实现一般不要求重写所有应用？

参考答案：同层实体遵守同一协议，具有逻辑通信关系，实际数据仍经本机下层和物理介质传输。只要层间服务接口及语义保持兼容，上层无需了解底层具体实现；但底层性能或可靠性变化仍会影响整体体验。

第二章　直连网络：把相邻两台设备连起来

2.1 数据、信号、码元与信道容量

对应：2A 第 4–20 页。

先区分三个对象：数据是要表达的信息符号；信号是它在电、光等介质中的表现；码元是一次选取的基本信号状态。单工只能单向，半双工双向但不能同时，全双工双向同时进行。

重点：码元速率的单位是 Baud，比特率的单位是 bit/s。若每个码元承载 log2M\log_2 M 个独立信息比特，Rb=Rslog2MR_b=R_s\log_2 M。

上式用于理想的 MM 状态映射；加入冗余编码时，还要区分信息速率和线路码元速率。基带编码改变数据对应的波形；载波调制改变高频载波的幅度、频率或相位，数字调制的典型对应为 ASK、FSK、PSK。

填空 F05　一个码元有 8 种等可能状态，理想情况下可表示________ bit；码元速率为 2000 Baud 时，信息速率为________ bit/s。半双工与全双工的关键差别是________。

参考答案：3；6000；能否同时进行双向传输。

难点：香农公式中的带宽 WW 是 Hz，不是已经给定的 Mb/s；公式中的 S/NS/N 是线性功率比，不能把分贝值直接代入。

C=Wlog2(1+S/N),SNRdB=10log10(S/N).C=W\log_2(1+S/N),\qquad \mathrm{SNR}_{dB}=10\log_{10}(S/N).

例题 E03｜课件中的香农计算　信道带宽 3000 Hz，信噪比 30 dB，求信道容量。

简答 S05　为什么“检错＋重传”常见？什么时候更适合使用前向纠错？

参考答案：错误较少且重传可行时，较少冗余的检错码加重传通常更经济。噪声较大、往返时延很长、重传代价高，或单工链路无法返回重传请求时，适合加入较强前向纠错。纠错也有能力边界，并非任何错误都能恢复。

2.6 ARQ 与滑动窗口：为什么要同时发多帧

对应：2B 第 31–48 页。

重点：可靠传输要处理差错、丢失、重复和顺序问题；ACK 表示收到，超时触发重传，序号用于识别重复及区分新旧帧。

停等每次只允许一帧未确认。原帧丢失、ACK 丢失或超时过早都会导致重传；收到重复数据帧时，不再向上交付，但应再次发送相应 ACK。0、1 交替序号在停等协议的正常时延与帧寿命假设下即可区分相邻两帧。

2.8 CSMA/CD、CSMA/CA 与以太网

对应：2C 第 23–70 页；作业讲解第 10–11 页。

重点：载波侦听只能知道本地此刻听到的状态；由于传播时延，两端仍可能先后都听到空闲并开始发送。因此“先听后发”不能彻底消灭碰撞。

  • 非持续 CSMA：忙时等待随机时间再听，减少持续争抢，但可能增加空闲等待。
  • 1-坚持 CSMA：忙时持续听，一旦空闲立即发；多个等待者容易同时发送。
  • pp-坚持 CSMA：在时隙模型下，空闲时以概率 pp 发，否则推迟到下一时隙再决定。

CSMA/CD 的流程：先听 → 空闲则发送，忙则继续听 → 边发边检测 → 碰撞则停止数据、发送干扰信号 → 随机退避 → 重试。第 kk 次碰撞通常从 00 到 2min(k,10)−12^{\min(k,10)}-1 中随机选一个整数，乘以时隙长度；传统以太网尝试达到上限后报告失败。

难点：1-坚持描述的是侦听到空闲后的发送策略；退避是发生碰撞后的重试等待，两者不矛盾。争用期为最远端往返传播时间 2τ2\tau，应满足 Lmin/R≥2τL_{\min}/R\ge2\tau。

CSMA/CA 的流程：侦听 → 按规则等待 DIFS／竞争退避 → 发送 → 等待 ACK；无 ACK 则按失败处理并重试。退避计数遇到忙信道会冻结，重新空闲满足间隔后再继续。RTS/CTS 可用于预约和缓解隐藏终端，不是所有帧都必须使用。

填空 F13　CSMA/CD 中 CD 表示________，CSMA/CA 中 CA 表示________；隐藏终端的典型情形是 A、C 互相听不到，却都向________发送。

参考答案：碰撞检测；碰撞避免；同一个接收结点 B。

简答 S08　为什么 Wi-Fi 采用碰撞避免？它能保证无碰撞吗？

参考答案：无线发送时自身信号远强于远端信号，难以同时可靠检测碰撞；隐藏终端又使本地侦听不能代表接收端情况。因此通过随机退避、ACK 和可选 RTS/CTS 尽量避免冲突。多个结点仍可能选中相同退避时间等，所以不能保证绝无碰撞。

重点：MAC 帧为 64–1518 B，数据部分为 46–1500 B；7 B 前导码和 1 B 帧开始定界符在其前面，不计入这 64–1518 B。普通以太网 MTU=1500 B 是上层分组的最大承载量。

MAC 地址长 48 bit，常写为 6 组十六进制数。全球管理地址由相关分配规则避免重复，本地管理、虚拟化或随机化场景下不能一概宣称“每张卡一生只有一个永不改变的地址”。广播 MAC 为 FF:FF:FF:FF:FF:FF。

填空 F14　以太网目的 MAC 为________ B，FCS 为________ B；上层 IP 包只有 40 B 时，无 VLAN 以太网至少填充________ B，得到________ B 的 MAC 帧。

参考答案：6；4；6；64。算式为 6+6+2+(40+6)+4=646+6+2+(40+6)+4=64。填充不应误算进 IP 首部的总长度。

集线器不等于“中心服务器”

Hub 在物理层复制和再生信号，通常从除输入端口以外的其他端口发出，不读取目的 MAC 决定转发；同一 Hub 下共享碰撞域与总带宽。它在物理上是星形，逻辑上仍是共享介质。

以太网有 CRC，但通常没有逐帧 ACK 或链路层丢失重传。接收到了信号，也不等于会把帧交给本机上层：网卡还要校验并按目的地址等条件筛选。

简答 S09　“Hub 把信号发给所有端口，类似服务器向用户上传视频”为什么不适合作为机制解释？现代以太网是否普遍还在运行 CSMA/CD？

参考答案：前者是物理层信号复制，没有应用服务角色，也不根据视频请求提供内容；C/S、P2P 是应用进程间的组织方式，两者层次不同。CSMA/CD 主要适用于传统共享式、半双工以太网；现代交换式全双工以太网不需要进行这类碰撞检测竞争，Wi-Fi 则采用 CSMA/CA。

第三章　交换网络：从共享介质走向按目的转发

3.1 自学习交换机：看源地址学习，看目的地址转发

对应：第 3 章第 2–10、21–23 页。

网桥与二层交换机在数据链路层工作，交换机可看作多接口网桥。转发表 FDB 记录 MAC 与端口的对应关系，并设置老化时间。

重点：学习依据“源 MAC＋入端口”；转发依据“目的 MAC”。未知单播和广播在所属 VLAN 的可转发端口内泛洪，排除入端口，不能原样送回输入链路。

对一帧的处理可以压缩为下面的过程，做题时每收到一帧就更新一次表：

从端口 i 收到有效帧
 → 用源 MAC 更新/刷新 FDB 的 (源MAC, i)
 → 查看目的 MAC
    已知且出端口不同于 i：从该端口转发
    已知且出端口就是 i：过滤，不向其他端口转发
    未知单播或需转发的广播：向同 VLAN 其他允许端口泛洪

“泛洪”是交换机的转发动作，并不会把原来单播帧的目的 MAC 改成广播 MAC。过滤是因为目的端已在收到帧的那一侧，不是交换机认为数据一定出错。

填空 F15　交换机从帧的________地址学习位置，根据________地址查询出端口；若查得出端口与入端口相同，则________该帧。

参考答案：源 MAC；目的 MAC；过滤／不再转发。

简答 S10｜逐帧填表　一台四端口交换机初始 FDB 为空，A 接端口 1，B、C 在端口 2 后同一个网段，D 接端口 3，端口 4 也处于同一 VLAN 的转发状态。依次发生 A→D、D→A、B→A、C→B，分别怎样学习和转发？

参考答案与过程：

收到的帧 本次学习 目的查询与动作
A→D，从 1 入 A→1 D 未知，向 2、3、4 泛洪
D→A，从 3 入 D→3 A 已知，仅从 1 出
B→A，从 2 入 B→2 A 已知，仅从 1 出
C→B，从 2 入 C→2 B 也在 2，过滤，不再转发

最终 FDB 为 A→1、D→3、B→2、C→2。最后一帧已经在 B 所在的共享网段上出现，交换机无需再把它送出去。

3.2 二层为什么怕环：生成树的完整推理

对应：第 3 章第 11–20 页。

冗余链路能提高可用性，但泛洪帧可能沿环路反复复制；普通以太网帧没有 IP 那样逐跳减一的 TTL，因而会造成广播风暴、重复帧、MAC 表项在端口间来回变化。

重点：生成树协议在保留物理冗余的同时，阻断部分转发端口，让活动拓扑形成无环生成树；故障后可以重新计算。它不是把多余电缆永久剪掉。

课件的简化配置消息为 （根桥标识，至根距离，发送桥标识），按字典序比较，越小越优：先比较根，再比较距离，最后比较发送者。

  1. 选根：标识最小的桥作为根桥。
  2. 选根端口：每个非根桥选择通往根的最佳路径端口。
  3. 选指派桥／指派端口：每个网段选择向根提供最佳路径的桥；距离相同则桥标识小者胜。
  4. 根端口和指派端口承担转发，其他冗余端口进入阻塞等非转发状态。

难点：生成树不是全图“总边权最小”的最小生成树算法。它先选一个根，再决定到根的优先路径和每段的指派端口；不要误套 Kruskal。

填空 F16　配置消息比较顺序为________、________、________；每个非根桥选一个________端口，每个网段选一个________端口。

参考答案：根桥标识；到根的距离；发送桥标识；根；指派。此处采用课件简化模型，真实 STP 还可用端口标识继续打破平局。

简答 S11｜三角形中的阻塞端口　B1、B2、B3 标识递增，两两用独立链路相连，各链路代价相同，其他条件相同。根是谁？B2—B3 链路哪一端阻塞？另比较消息（B1,2,B4）和（B1,1,B5）。

参考答案：B1 是根；B2、B3 的根端口都直连 B1。在 B2—B3 网段上，两桥到根的代价相同，B2 标识小，B2 侧为指派端口；B3 侧既非根端口又非指派端口，阻塞。两条消息中（B1,1,B5）更优，先比距离 1<2，不会越过距离先比 B4 与 B5。

补充：课件主要列 Forwarding、Blocking、Disabled 三种端口状态，先按这三种理解。传统 802.1D 还有监听、学习等过渡状态，RSTP 的分类又不同；没有被要求时不要混写成同一套状态表。

3.3 碰撞域、广播域与 VLAN

对应：2C 第 66–69 页；第 3 章第 7、21–27 页。

设备／划分 是否按地址选择转发 碰撞域 广播域
中继器、Hub 不查看 MAC 多端口仍共享 不隔离
二层交换机 按 MAC 和 VLAN 隔离不同端口链路；全双工链路无共享式碰撞 默认同 VLAN 仍在一个广播域
VLAN 按逻辑组限制二层转发范围 沿用各链路情况 不同 VLAN 分开
路由器／三层转发 按 IP 前缀 分开链路 通常不转发二层广播，隔离不同广播域

重点：交换网络仍然存在广播；“交换机把共享的单播扩散变成按需单播”不等于“交换机消除了广播域”。VLAN 间通信通常要经过路由器或三层交换。

802.1Q 在以太网帧中增加 4 B 标签；其中 VLAN ID 占 12 bit，但不能简单把 4096 全部当作可分配给普通 VLAN 的编号。基础常识为 VID 1–4094 可用，0、4095 保留特殊含义。接入口的终端帧通常不带标签，跨交换机的 Trunk 承载多 VLAN 的标签帧；不能背成“所有经过 VLAN 的帧在所有链路上都必定带标签”。

填空 F17　802.1Q 标签长度为________ B；它主要支持区分________。一台交换机上划出两个 VLAN，在没有三层转发的前提下，二者属于________个二层广播域。

参考答案：4；VLAN；2。

简答 S12　8 台主机在同一台 Hub 上，与分别接入全双工交换机的 8 个端口，有什么性能差异？“交换机有 8 个百兆端口，所以任意一条流可达到 800 Mb/s”对吗？

参考答案：Hub 下共享介质与碰撞域，多个发送会互相竞争。交换机可让多对互不争用同一输出端口的主机并行通信，每条全双工链路拥有自己的带宽。但任意单端口上的流仍受百兆限制，多个输入汇聚到同一输出会排队；内部交换容量和统计口径也影响总吞吐量，因此不能直接断言单流 800 Mb/s。

第四章　网络互联：统一编址与逐跳交付

4.1 为什么有了 MAC 还需要 IP

对应：4A 第 3–17、19–40 页。

重点：IP 用统一的分组和层次化地址连接异构网络，提供无连接、尽最大努力的数据报服务，不保证不丢失、不乱序、不重复或有确定时限。

MAC 适合当前二层网络中的交付，通常不反映全球网络拓扑；IP 前缀能聚合一组地址，从而缩小路由信息规模。转发是某路由器把当前包移向出接口的局部动作；路由选择是计算路径、形成路由信息的控制过程。

虚电路先建立逻辑路径、维护相应连接状态；数据报方式让各包独立携带目的信息并被转发。虚电路不必等于物理独占电路，也不因“有连接”就自动保证任何实现都绝无差错或丢失。

简答 S13　在没有 NAT 等地址改写的普通路由场景下，IP 源、目的地址与 MAC 源、目的地址分别怎样变化？

参考答案：IP 源、目的地址保持原来的通信端点；每经过一次路由转发，原链路帧被解封，出接口重新组帧，源 MAC 改为本跳发送接口，目的 MAC 为本链路上的下一跳接口。若只是经过透明二层交换机，不能说交换机也把源 MAC 换成自己的 MAC。

4.2 FIB、下一跳与 ARP：先决定往哪走，再找这一跳的 MAC

对应：4B 第 5–20 页；4C 第 21–27、38–42 页。

FIB（转发信息库）记录目的前缀／掩码、下一跳或出接口。普通主机也需要路由选择，例如向本地网络直接交付，或通过默认网关离开本网络。

重点：路由决定下一跳 IP，ARP 查询本链路上这个下一跳的 MAC。目的主机在异地网络时，本机通常 ARP 默认网关，不是跨越整个 Internet 去广播寻找远端主机。

正常的同网段以太网 ARP 过程：查缓存 → 无表项则广播 ARP 请求 → 目标主机通常单播应答 → 学习映射、缓存并发送帧。请求和应答直接由以太网承载，EtherType 为 0x0806，没有外套 IP 首部；IPv4 数据帧的 EtherType 为 0x0800。

目的 IP D
 → 对路由表各前缀做匹配，选最长匹配项
 → 直连路由：下一跳就是 D
   经网关路由：下一跳是所选网关 G
 → 在出接口所属链路查 ARP(D 或 G)
 → 获得目的 MAC，封装帧并发送

难点：ARP 查询与路由表查询是两张不同的表。交换机 FDB 记 MAC→端口，ARP Cache 记本地链路 IP→MAC，FIB 记前缀→下一跳／接口。

填空 F19　常规 ARP 请求通常采用________，应答通常采用________；以太网＋IPv4 的 ARP 报文中 HLen 应填________，PLen 应填________，这两个长度的单位为________。

参考答案：广播；单播；6；4；字节。4B 第 20 页的示意标为 48、32，指的是地址的比特长度；报文长度字段实际填的是 6、4，不应混淆。

简答 S14｜跟着老师的子网例子走一遍　H1 为 128.30.33.13/25，H2 为 128.30.33.138/25。R1 的同侧接口为 128.30.33.1，另一侧接口为 128.30.33.129。H1 怎样把一个 IP 包交给 H2？假设没有现成 ARP 缓存。

参考答案与过程：

  1. H1 用自己的 /25 掩码计算：本地网络为 128.30.33.0，H2 对应网络为 128.30.33.128，不同。
  2. H1 根据路由将下一跳选为 128.30.33.1，ARP 查询 R1 同侧接口的 MAC。
  3. 第一跳帧的源 MAC 为 H1，目的 MAC 为 R1；IP 源仍是 H1，IP 目的仍是 H2。
  4. R1 解出 IP 包，匹配到直连网络 128.30.33.128/25，从另一侧接口转发，ARP 查询 H2 的 MAC。
  5. 第二跳帧的源 MAC 为 R1 的出接口，目的 MAC 为 H2。R1 转发时还需处理 TTL、首部校验和等。

填空 F20　IHL=6 表示首部________ B；总长度 1024 B 时数据为________ B。首部校验和是否覆盖载荷？________。TTL=1 的普通数据报到达需要继续转发的路由器时通常会________。

简答 S15　IP 源、目的地址都没变，路由器为什么还要更新首部校验和？

参考答案：因为 TTL 在转发时发生变化，校验和覆盖的首部已经改变；分片时总长度、标志、偏移等也可能改变。因此需更新校验和，但并不要求每跳重算 IP 数据部分的校验和。

4.4 IPv4 分片与重组：先减首部，再做 8 字节对齐

对应：4B 第 35–42 页。

重点：DF=1 表示禁止分片；MF=1 表示后面仍有分片。每片都带 IP 首部，同一原报文各片使用相同标识，通常由最终目的主机重组。

首部固定为 HH B、出链路 MTU 为 MM B 时，非最后一片的最大数据长度为：

Dmax=8⌊M−H8⌋.D_{\max}=8\left\lfloor\frac{M-H}{8}\right\rfloor.

片偏移 == 本片数据在原始数据部分中的起始字节位置 /8/8；总长度 =H+=H+ 本片数据长度。非最后片的数据长度须为 8 的倍数，不是要求含首部的整片总长度为 8 的倍数。

填空 F21　MTU=1500 B、IP 首部 20 B 时，非最后一片最多带________ B 数据。第二片若从原数据字节位置 1480 开始，片偏移字段应为________。

参考答案：1480；185。

例题 E08｜课件 3800 B 数据的分片　原 IPv4 数据部分 3800 B，无选项首部 20 B，DF=0，经 MTU=1420 B 的链路，尽量装满各分片。

参考答案与过程：原总长为 3820 B；Dmax=8⌊(1420−20)/8⌋=1400D_{\max}=8\lfloor(1420-20)/8\rfloor=1400 B；数据分为 1400、1400、1000 B。

分片 原数据字节范围 数据长度/B IP 总长度/B 片偏移 MF
1 0–1399 1400 1420 0 1
2 1400–2799 1400 1420 175 1
3 2800–3799 1000 1020 350 0

三片 Identification 相同，DF 均为 0。数据总量仍为 3800 B，但多出两个 IP 首部，所以共发送 3820+2×20=38603820+2\times20=3860 B 的 IP 层数据。

难点：片再次分片时，偏移仍相对最初的数据报；“最后一片”的 MF 应继承原片是否还有后续的含义，不能看见本次拆分的最后一块就机械置 0。

小补充：若 DF=1 而 MTU 不足，路由器不能擅自分片，通常丢弃并用 ICMP 提示需要分片，支持路径 MTU 发现。分片丢失使重组无法完成，IP 本身不负责重传。课件“IPv6 废止分片”应理解为IPv6 路由器不分片，源主机仍可使用分片扩展首部，不能说 IPv6 完全不存在分片。

4.5 子网划分：先算需要几位，再算边界

对应：4C 第 5–28 页。

重点：网络地址 N=IPANDmaskN=IP\ AND\ mask。前缀长度为 pp，地址数 232−p2^{32-p}；普通广播型 IPv4 子网的可分配主机数通常为 232−p−22^{32-p}-2，减去网络地址和广播地址。

做题固定按五步：

  1. 写原始网络／前缀，确认可用地址范围。
  2. 由主机需求求主机位 hh，使 2h−2≥H2^h-2\ge H。
  3. 求新前缀 p=32−hp=32-h，同时检查子网数量是否足够。
  4. 按块大小列网络边界，主机位置全 0 为网络、全 1 为广播。
  5. 可用范围为网络地址＋1 到广播地址−1，并检查不重叠、不越界。

常见尾字节掩码：/25→128，/26→192，/27→224，/28→240，/29→248，/30→252；对应块大小为 128、64、32、16、8、4。遇到 /18、/20 等跨第三字节边界的题目，仍用相同二进制原理。

填空 F22　192.168.10.77/26 的网络地址为________，广播地址为________，可用主机范围为________，普通可用主机数为________。

参考答案：192.168.10.64；192.168.10.127；192.168.10.65–192.168.10.126；62。块大小为 64，77 落在 64–127。

两种子网计数口径一定要区别

难点：课件 4C 第 14、17–20 页采用 RFC 950 的旧规则，借 ss 位后的可用子网数为 2s−22^s-2，排除全 0 和全 1 子网；现代 CIDR／常规子网规划通常允许它们，子网数为 2s2^s。

原课件例题若明确沿用该旧规则，就按旧规则列子网，并在答案中写清口径；新题没给限制时，不应悄悄把旧禁用规则当作普遍现行规定。全 0／全 1 的“子网号”与全 0／全 1 的“主机号”也不能混为一谈。/31 点到点链路和 /32 主机路由另有用途，不能机械套普通主机数减 2 公式。

4.6 CIDR、聚合和最长前缀匹配

对应：4C 第 30–42 页。

子网划分让前缀变长，把大块拆小；路由聚合通常让前缀变短，用一个大块代表多个更具体的前缀。好处是提高地址分配灵活性、压缩对外路由信息。

重点：精确聚合成一个 CIDR 块，地址应连续、范围大小是 2 的幂，并且起始地址满足块边界对齐；路由上还应具有可统一表达的下一跳／出口关系。

例如课件的 192.4.16.0/24 到 192.4.31.0/24，共 16 个连续 /24，第三字节高 4 位相同，可聚合为 192.4.16.0/20。193.14.32.0/20 共 4096 个地址，范围为 193.14.32.0–193.14.47.255。

难点：几个地址“相邻”还不够。192.168.1.0/24 与 192.168.2.0/24 不能精确聚合成 /23；包含两者的最小单一 CIDR 是 192.168.0.0/22，它还覆盖额外地址。

查表时对各候选执行 (DANDmaski)=prefixi(D\ AND\ mask_i)=prefix_i，所有匹配项里选前缀位数最多的一项。默认路由 /0 最不具体，主机路由 /32 最具体。最长前缀比较的是本次目的地址匹配程度，不是路径跳数最少，也不是 IP 十进制数最大。

参考答案：4096；/22；/24。

4.7 跨章综合：完整讲完一次异网通信

简答 S16　A 要向另一 IP 子网的 B 发送数据，路径中有二层交换机和路由器。请依次说明路由、ARP、交换学习、分片及接收各负责什么。

参考答案：A 的网络层先根据路由判断下一跳，必要时 ARP 查询本地网关 MAC，再把 IP 包封装成以太网帧。交换机从源 MAC 学习入端口，并按目的 MAC 转发或泛洪，不替 A 计算跨网的 IP 路径。路由器解封链路帧、校验并更新 IP 首部、按最长前缀匹配选择下一跳，再在出链路解析所需硬件地址并重新封装；若 IPv4 包超过 MTU 且允许分片，则按规则分片。到达 B 后进行必要重组、解封并交给相应上层协议。链路 CRC 用于检错，IP 仍尽力交付；端到端可靠性需由相应上层协议提供。

ICMP：反馈与诊断，不负责把原数据重新送一遍

重点补充：ICMP 传递 IP 层的差错和控制信息，由 IP 承载，Protocol=1；它不是可靠传输协议。

  • ping 常利用 Echo Request／Reply 检查可达性并测量往返时间。
  • TTL 耗尽通常触发 Time Exceeded；无法到达等情况可能触发 Destination Unreachable。
  • traceroute 类工具逐步增大 TTL，利用中途的超时反馈发现路径；不同系统可发 UDP、ICMP 或 TCP 探测。
  • 没收到 ICMP 不必然证明目的主机断网，报文也可能被过滤或限速。不是每一种丢包都会引起 ICMP 差错反馈。

多播、VPN 与 NAT：三个不同的问题

多播把数据发送给一个接收组，IPv4 组地址位于 224.0.0.0/4；它不等于向同一 LAN 所有人广播。IGMP 用于 IPv4 主机与相邻多播路由器之间的组成员管理，不负责全网最短路径计算。

VPN在公共或共享基础设施上构造逻辑上的专用网络，常采用隧道；具体方案是否以及怎样加密，取决于协议和配置。“有隧道”并不自动等于“端到端全部内容都安全”。

NAT／NAPT在边界改写地址，NAPT 还用端口区分多个会话，让多台内部主机共享公网地址。它会成为“普通 IP 源、目的地址沿途不变”结论的例外。NAT 不等于防火墙，也不能仅凭使用私网就推断可直接访问公网。
