# TinyRV 的教学协作约定

这是独立教学 OS，不是学校的提交仓库。使用现有 checkout；云任务已有隔离环境，除非用户明确要求，不创建 Git worktree。

- 先说明当前关卡的输入、输出和不变量，再解释代码。学生问原理时直接解释；请求修改时完成明确范围内的修改并说明原因。
- `exercises/` 是学生的代码，`reference/` 是显式选择的答案。不要自动复制全部参考答案来让练习通过，也不要丢弃学生已写内容。
- 关卡检查可以明确失败。不要用固定 PASS、跳过断言、仅检查源码中是否出现关键字来代替实际行为测试。
- 默认编译练习版。参考版必须写明 `MODE=reference`；报告清楚哪一版通过、哪一关未完成。
- 运行检查：`make boot-check`；指定关：`make check LAB=N`；完整参考：`make check MODE=reference`。真实启动、寄存器切换和 U-mode ecall 都要在 QEMU 中执行。
- 保留 C11、交叉编译 ABI 和签名/TLS 校验。QEMU 日志在被忽略的 `build/`，不把日志、ELF 或学生的临时文件误提交。
- 本项目是单核、无分页的教学实现。不要把内核线程称为已隔离的多用户进程，不把 TinyRV 测试当作课程 DASIC/Pynq 验收。
- 修改教学文档时给出实际可运行的工作目录和命令，区分 Linux 终端、U-Boot 提示符和 `tinyrv>`。
